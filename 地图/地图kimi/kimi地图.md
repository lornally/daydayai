# 中国中心世界地图 — 技术演进文档

> 用 Python + Cartopy 生成以中国为中心的世界地形图。
> 核心挑战：标准伪圆柱投影的赤道和中央经线固定，无法直接让任意纬度（如 35°N）成为新赤道。解决方案：**球面坐标旋转**。

---

## 一、核心设计决策

### 问题背景

用户需要一个**完整地球**、**中国位于正中心**（x+y 双方向）、**带 3D 地形**的世界地图。常见方案的问题：

| 方案 | 问题 |
|------|------|
| 方位等距投影 | 边缘变形严重，南半球崩坏 |
| 等差分纬线多圆锥投影 | 中心经线固定为 150°E，太平洋居中 |
| 简单裁剪/平移 | 只显示半个地球，违背投影原理 |
| 标准 Robinson/EqualEarth + 中央经线 103°E | x 方向居中，y 方向不居中（赤道固定） |

### 解法：球面坐标旋转（Oblique Transformation）

不寻找"支持偏心纬度的伪圆柱投影"（数学上不存在），而是**旋转数据**：

1. 将目标中心点（如 103°E, 35°N）通过欧拉角旋转映射到新坐标系的 (0°, 0°)
2. 在新坐标系中，标准 Robinson/EqualEarth 的赤道+中央经线自然穿过中国
3. 对新坐标系的数据做标准投影，得到 x+y 双方向居中的完整地球

这等价于天文学中的"黄道坐标系转赤道坐标系"，或 GIS 中的"斜轴等面积投影"思想。

## 二、版本演进

### v1 — 基础地图（2026.5.16）

**目标**：验证技术可行性，快速出图。

- 投影：Robinson、EqualEarth、Mollweide
- 中心经线：103°E（仅 x 方向居中）
- 底图：Cartopy 内置 `stock_img()`（720×360，低分辨率）
- 风格：hypsometric（彩色晕渲）、shaded_relief（浮雕阴影）、minimal（简洁）
- 问题：y 方向未居中，中国偏下；底图分辨率极低

### v2 — 纵向裁剪（被否决）

**尝试**：用 `set_ylim` 限制 y 范围实现"视觉居中"。

- 结果：只显示半个地球
- 结论：违背"完整地球"需求，方案废弃

### v3 — 斜轴旋转（2026.5.16-17）

**突破**：引入球面坐标旋转，实现真正的 x+y 双方向居中。

**关键技术**：

```
原始坐标 (lon, lat)
    ↓
绕 Z 轴旋转 -clon  → 经度归零
绕 Y 轴旋转 clat   → 纬度归零（目标点移到新赤道）
绕 Z 轴旋转 180°   → 中国面向观察者
    ↓
新坐标 (lon', lat') — 在新坐标系中标准投影
```

**数据管线**：

| 数据类型 | 处理方式 |
|---------|---------|
| Raster 底图（10800×5400） | `scipy.ndimage.map_coordinates` 球面重采样 |
| 海岸线/国界/河流（矢量） | `shapely` 逐顶点旋转 + ±180° 经线分割 |
| 中心标记 | 新坐标系 (0, 0) 处绘制红色十字 |

**底图升级**：
- v1: stock_img (720×360) → 模糊
- v2: NASA Blue Marble Shaded Relief (10800×5400) → 分辨率 OK，但海洋过亮
- v3: **NASA GIBS ASTER GDEM Color Shaded Relief** (10800×5400) → 自带高程分层设色+山体阴影

**产出**：12 张图（2 中心点 × 3 投影 × 2 风格）

**遗留问题**：
- shaded_relief 风格下，cartopy 动态加载的矢量要素（OCEAN/LAND/COASTLINE）与旋转后的 raster 底图存在空间偏移
- 底图为预渲染 JPG，颜色 baked，无法自定义分层设色（如区分草原/沙漠/森林）

### v4 — 错位修复 + 海洋压制（2026.5.17）

**修复 shaded_relief 错位**：

根因：cartopy `cfeature.OCEAN` 是独立矢量图层，坐标未经过与底图一致的球面旋转。

解法：放弃 cartopy 动态 ocean feature，改用**颜色阈值法**直接替换 ASTER GDEM 中的海洋像素：

```python
# ASTER GDEM 海洋特征：蓝色通道显著高于红/绿
is_ocean = (B > G + 0.05) & (B > R + 0.05) & (R < 0.45)
# 替换为深蓝 (26, 58, 92) → 准确率 ~69%（接近地球 71% 海洋比）
```

优势：
- 矢量与 raster 完全一致（同一套旋转坐标）
- 无错位、无边缘 artifact
- 海洋颜色统一、压暗，凸显陆地地形

**产出调整**：
- 去掉 Mollweide（用户未选择）
- 去掉 minimal 风格
- 8 张图：2 中心点 × 2 投影 × 2 风格

## 五、已知局限

### 1. 地形精细度天花板

当前 ASTER GDEM Color Shaded Relief 是**预渲染图**，颜色已 baked：

- 无法区分森林/草原/沙漠（颜色反映高程+阴影，非土地覆盖）
- 无法自定义色阶（如用户要求的"沙漠黄色、森林绿色、草原浅黄绿"）
- 无法独立调整山体阴影强度 vs 高程分层设色强度

**甘肃底图精度**的实现路径（参考视频教程）：
```
DEM 高程数据
    → ArcGIS Pro 高程分层设色（Hypsometric Tinting）
    → Aerialod 3D 渲染（独立控制山体阴影）
    → PS 微调（曝光/饱和度/对比度）
```

等价 Python 路径需：
1. **原始 DEM**（非预渲染图）：ETOPO1 / GEBCO / SRTM
2. **土地覆盖图层**：ESA WorldCover / MODIS Land Cover
3. **自计算山体阴影**：`numpy` 按光源方位角/高度角计算 hillshade
4. **自定义 colormap**：`matplotlib.colors.LinearSegmentedColormap`
5. **叠加合成**：高程色 × hillshade（multiply/soft-light 混合模式）

### 2. 全球 vs 区域的数据矛盾

甘肃底图（7000×7000px，区域级）可用 30m SRTM DEM，全球同等精度需 ~1.4TB 数据。当前 10800×5400（约 2km/px）是**全球尺度下兼顾精度与可行性**的平衡点。

### 3. 矢量数据来源

Natural Earth 1:110m 对全球概览足够，但国界线精度有限。中国标准国界线应以 `bzdt.ch.mnr.gov.cn` 为准。

## 六、未来路线（v5）

### 方案 A：全球 DEM 自渲染（工程量大，效果最优）

1. 下载 GEBCO 2023（全球 15 弧秒，~1.4GB GeoTIFF）
2. 计算山体阴影（azimuth=315°, altitude=45°）
3. 叠加 ESA WorldCover 土地覆盖（森林/草原/沙漠/城市分类着色）
4. 自定义高程色表 + 混合模式
5. 球面旋转 → 投影输出

**瓶颈**：数据下载、内存占用（高分辨率全球 DEM 旋转需数十 GB RAM）、 land cover 与 DEM 的配准。

### 方案 B：ASTER GDEM 后处理（折中，当前方向）

在不换数据源的前提下，通过图像处理增强：

1. 从 ASTER GDEM 中**反推高程近似值**（基于颜色-高程统计关系）
2. 叠加 MODIS Land Cover 分类图层（NASA GIBS 提供 WMS 服务）
3. 按 land cover 类型调整色相：
   - 森林 → 保持/增强绿色
   - 草原 → 偏浅黄绿
   - 沙漠/戈壁 → 偏黄色
   - 高山/雪原 → 白色/棕白
4. 海洋区域统一压暗（v4 已实现）

**瓶颈**：ASTER GDEM 颜色信息混杂了高程+阴影+地表覆盖，反推和分离的准确度有限。

### 方案 C：局部精修（PS 后处理）

Python 生成基础图 → Photoshop/GIMP 手动精修关键区域（中国、青藏高原、安第斯等）→ 输出最终版。这是"他山之石"视频作者的实际工作流。
